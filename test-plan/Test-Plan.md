# Test Plan

## 1. Project Overview

This project is an end-to-end QA case study for the Practice Software Testing e-commerce application.

The purpose of the project is to validate a complete user flow from registration to order creation by combining manual testing, API validation, SQL/database checks, defect reporting, and basic test design techniques.

## 2. Test Objectives

- Verify that the main end-to-end user flow works as expected.
- Validate critical user actions such as registration, login, product search, cart operations, and checkout.
- Compare UI behavior with API responses where applicable.
- Validate relevant data using SQL/database checks.
- Identify and document functional defects.
- Apply appropriate test design techniques to selected scenarios.

## 3. Scope

### In Scope

- User Registration
- Login
- Product Search
- Product Detail
- Shopping Cart
- Checkout / Order Creation
- Selected API validations
- Selected database validations

### Out of Scope

- Performance Testing
- Load Testing
- Security Testing
- Full API coverage
- Full database testing
- Test Automation

## 4. Test Approach

- Manual functional testing will be used to validate the main user journey.
- Positive and negative test scenarios will be executed for critical features.
- Exploratory testing will be used to identify unexpected behavior.
- API requests will be used to validate selected backend operations.
- SQL queries will be used to verify selected database records and relationships.
- Regression testing will be performed on critical flows after important changes or defect verification.

## 5. Test Environment

- Operating System: Windows 11
- Browser: Google Chrome
- Application: Practice Software Testing
- API Tool: Postman
- Database: PostgreSQL
- Database Tool: pgAdmin
- Version Control: Git / GitHub

## 6. Entry Criteria

- The application must be accessible.
- Required test accounts and test data must be available.
- The selected API endpoints must be accessible.
- The test database must be available for validation.
- The main user flow must be available for testing.

## 7. Exit Criteria

- All planned critical test cases have been executed.
- Critical defects have been documented.
- Selected API validations have been completed.
- Selected database validations have been completed.
- The end-to-end user flow has been evaluated.
- Test results have been documented in the final test summary.

## 8. Deliverables

- Test Plan
- Test Scenarios
- Test Cases
- API Validation Notes
- SQL / Database Validation Queries
- Bug Reports
- Test Summary Report
